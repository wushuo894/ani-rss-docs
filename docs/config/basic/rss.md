# RSS 设置

### RSS开关

用于总开关控制 RSS 轮询任务。

关闭后，程序不会继续按计划检查订阅更新，但已有配置和历史数据仍会保留。

### RSS 间隔

RSS 轮询间隔，单位：分钟。

设置越小，检查更新越及时；设置越大，对源站和本机的压力越小。订阅数量较多时，不建议设置得过于激进。

界面允许的最小间隔为 `10` 分钟。

### RSS 超时 {#rss-timeout}

RSS 请求超时时间，单位为秒，界面可设置范围为 `6–60` 秒。网络较慢时可适当增加，并检查代理与源站状态。

### 自动跳过 {#auto-skip}

自动检测季度文件夹下是否已经下载某集

::: warning
此选项 **必须启用自动重命名**。确保 **下载工具**、 **ani-rss** 的 Docker 映射挂载路径 **保持一致**
:::

### 自动禁用订阅 {#自动禁用订阅}

根据 Bangumi 获取总集数，当所有集数都已下载时自动禁用该订阅

### 自动更新总集数 {#update-total-episodes}

这是独立于“自动禁用订阅”的开关。启用后，后台每轮检查启用中的订阅，再等待 12 小时进行下一轮检查。

- 未开启“强制更新”时，仅补全总集数为 `0` 的订阅，保留已有的非零总集数。
- 开启“强制更新”后，会按 Bangumi 返回的数据更新已有总集数，也可能覆盖手工填写的值。

### 订阅完结迁移 {#completed-migration}

在“自动禁用订阅”下启用“订阅完结迁移”，并填写迁移位置。路径支持与[下载保存位置](/config/download#save-path)相同的模板变量，例如：

```txt
/Media/已完结番剧/${title}/Season ${season}
```

迁移需要同时满足：全局“自动禁用订阅”和“订阅完结迁移”已开启；订阅自身开启“完结迁移”；总集数大于 `0`、进度已达到总集数，且订阅已禁用。剧场版不参与迁移。

程序在处理下载完成时尝试迁移，调整相关下载任务的保存位置，并移动原目录中的文件。订阅的“自定义完结迁移”可覆盖全局目标路径。使用 Docker 时，迁移前后的目录都需要让程序和下载器以相同路径访问。

### 自动跳过X.5集

开启后，RSS 解析时会过滤集数为 `12.5`、`13.5` 等 `.5` 的条目，不会将其加入下载。

关闭后可识别和下载这些条目，并按 `S01E12.5` 这样的格式重命名。程序不会将它们自动映射为 `S00E0X` 特别篇编号，TMDB 剧集刮削也会跳过 `.5` 集。

### 遗漏检测

检测最小集数与最大集数之间是否存在遗漏

若有遗漏会自动发送通知

::: warning
缺少集数大于 10 个时可能是误判，因此不进行通知
:::

### 摸鱼检测 {#procrastinating}

可设置检测天数

全局开关与订阅自身的“摸鱼检测”均开启时生效。界面可设置 `7–365` 天；距离最近一次 RSS 发布时间超过设定天数时发送通知。

默认勾选“仅启用主 RSS 摸鱼检测”，仅依据主 RSS 判断；取消后会把备用 RSS 一起纳入判断。进度已达到已知总集数的订阅不再检测摸鱼。

建议配合 [自动禁用订阅](#自动禁用订阅) 使用，并在[通知](/config/notification#notification-status)中选择“摸鱼检测”状态。

适合追更中的周更番：如果一段时间没有更新，可以更快发现字幕组断更、源站停更、订阅填错或 RSS 失效等情况。

### 备用 RSS {#back-rss}

当 `主 RSS` 未更新时会先行下载 `备用 RSS`，`主 RSS` 更新之后则会把 `备用 RSS` 覆盖掉

适合以下场景：

- 主字幕组更新慢，但你又希望先看
- 希望先用备用源兜底，后续再自动洗版为主源版本
- 部分番剧不同字幕组发布时间差异较大

::: details 多字幕组共存模式
开启此模式后 `主 RSS` 与 `备用 RSS` 将可以同时被下载

需要重命名模板中包含 `[${subgroup}]`
:::

#### 如何洗版？

::: info

- 推荐使用默认重命名模板
- 对 TR 与 Aria2 的兼容性不太稳定
- 关闭 多字幕组共存模式
- 开启 自动删除
- 关闭 自动跳过

:::

::: warning
需要映射路径与下载器一致，否则若旧视频为 MP4 新视频为 MKV 时无法完成自动删除旧视频。

Windows 平台开启自动删除可能会出现文件被占用无法删除的问题，这是 Windows 的特性（💩）
:::
