# 🚀 快速开始

这篇指南会带你完成第一次自动追番：启动 ANI-RSS，连接下载器，添加一个订阅，并将视频下载到指定目录。

ANI-RSS 负责检查 RSS 更新、筛选资源并管理下载任务，实际下载由下载器完成。开始前，请准备好一个下载器和一个有写入权限的媒体目录。下面以 **qBittorrent** 为例；其他下载器见[下载设置](/config/download)。

## 1. 部署并登录

根据运行环境选择一种部署方式，按对应页面完成安装和启动：

| 运行环境 | 部署教程 |
| --- | --- |
| NAS、家庭服务器或已安装 Docker 的设备 | [Docker 部署](/deploy/docker) |
| Linux 主机，直接运行或安装为系统服务 | [Linux 部署](/deploy/linux) |
| Windows 电脑 | [Windows 部署](/deploy/windows) |
| macOS 电脑 | [macOS 部署](/deploy/macos) |

启动后，在浏览器打开：

```txt
http://127.0.0.1:7789
```

如果 ANI-RSS 运行在另一台设备上，将 `127.0.0.1` 换成那台设备的 IP；如果修改了端口或 Docker 端口映射，使用实际访问端口。

默认用户名和密码均为 `admin`。登录后，进入 **设置 → 安全** 修改默认账号密码，点击页面顶部的 **保存**。账号与访问控制的详细说明见[安全设置](/config/security)。

## 2. 连接 qBittorrent

先在 qBittorrent 中启用 **WebUI**，确认能通过浏览器打开，再在其设置中生成 API 密钥。

进入 ANI-RSS 的 **设置 → 下载设置**，填写：

| 配置项 | 填写内容 |
| --- | --- |
| 下载工具 | `qBittorrent` |
| 地址 | qBittorrent 的 WebUI 地址，例如 `http://192.168.1.10:8080`，按实际 IP 和端口填写 |
| ApiKey | qBittorrent 生成的 API 密钥，以 `qbt_` 开头 |

点击 **测试**，提示登录成功后继续配置保存位置。

::: tip 两个程序的凭据各有用途
这里填写的是 **qBittorrent 的 API 密钥**。ANI-RSS 的登录账号密码用于访问管理页面；“设置 → 安全”中的 API Key 用于扩展、脚本等第三方工具连接 ANI-RSS。
:::

下载器地址必须能从 **ANI-RSS 所在的运行环境** 访问。如果两个程序运行在不同容器中，使用普通桥接网络时，`127.0.0.1` 指向 ANI-RSS 容器自身，应改用可达的下载器地址。同一 Docker 网络中可使用下载器的服务名和容器端口；使用本文档的 host 网络部署示例时，按[部署页](/deploy/docker)填写。

## 3. 设置保存位置

在 **设置 → 下载设置** 中填写媒体保存路径。Linux / Docker 环境可使用以下模板：

| 配置项 | 示例 |
| --- | --- |
| 保存位置 | `/Media/番剧/${title}/Season ${season}` |
| 剧场版保存位置 | `/Media/剧场版/${title}` |

`${title}` 会替换为订阅标题，`${season}` 会替换为季数。例如，标题为“示例番剧”、季为 `1` 时，番剧将保存到：

```txt
/Media/番剧/示例番剧/Season 1
```

Windows 和 macOS 默认使用当前用户 `Downloads` 下的目录，可保留页面中的默认模板，也可改成自己的媒体目录。更多变量见[保存位置](/config/download#save-path)。

### Docker 的媒体目录如何挂载？

**ANI-RSS 与下载器需要通过相同的容器内路径访问同一份媒体文件。** 例如，宿主机媒体目录是 `/volume2/Media`，两个容器都应挂载为 `/Media`：

| 容器 | 宿主机目录 | 容器内目录 |
| --- | --- | --- |
| ANI-RSS | `/volume2/Media` | `/Media` |
| qBittorrent | `/volume2/Media` | `/Media` |

此时，在 ANI-RSS 保存位置中填写 `/Media/番剧/${title}/Season ${season}`，并确保两个容器都能读写该目录。宿主机目录可按实际情况调整，完整配置见[Docker 部署](/deploy/docker)。

如果下载器能下载，但 ANI-RSS 无法访问对应文件，自动跳过、下载完成后的重命名等功能就可能无法正常工作。

配置完成后，点击页面顶部的 **保存**。**测试成功只代表下载器连接可用，不会代替保存设置。**

## 4. 添加第一个订阅

先选择一部已有更新的番剧，完成一次下载后再添加更多订阅。

1. 打开 **订阅** 页面，点击 **添加 → 添加订阅**。
2. 选择 **Mikan**、**AniBT** 或 **AnimeGarden**，点击对应的“浏览”按钮，选择作品与字幕组；已有 RSS 链接时，也可直接在对应来源中粘贴地址，点击 **下一步**。
3. 解析完成后，在订阅编辑界面确认 **标题、季、主 RSS、集数偏移**。第一次添加时，可先保留其他选项的默认值。
4. 点击 **预览**，查看识别出的集数、重命名结果，以及最终下载目录。
5. 确认 **启用** 已开启，再完成添加。

请使用 **单个番剧、单个字幕组的 RSS**。使用“其他”来源时，还需填写番剧名称并选择对应的 Bangumi 条目。

::: tip 只追新集还是补全旧集？
添加前留意 **只下载最新集**：开启时只下载最新条目及同日发布的条目，无法比较发布时间时仅保留最新条目。想补下 RSS 中已有的旧集，请关闭它；RSS 已经不包含的剧集，可通过[合集下载](/collection)补番。
:::

订阅字段的详细说明见[添加订阅](/add-rss)。例如，RSS 从第 `13` 集开始，而你希望这一季从第 `1` 集编号，可将集数偏移设为 `-12`，再通过预览确认结果。

## 5. 完成第一次下载

进入 **设置 → 基本设置 → RSS 设置**，确认 **RSS 开关** 已开启并保存。程序会按 RSS 间隔检查更新，也可以在订阅页面点击 **刷新** 并确认，手动触发一次检查。

依次观察以下结果：

1. **ANI-RSS 能读取资源**：订阅预览中出现 RSS 条目，集数与筛选结果符合预期。
2. **qBittorrent 收到任务**：下载器中出现对应种子任务并开始下载。
3. **视频保存到预期目录**：下载完成后，能在第 3 步设置的位置找到文件；开启自动重命名时，文件名也应符合模板。

完成这三步后，后续更新就会按配置自动检查和下载。

### 遇到问题时

| 现象 | 优先检查 |
| --- | --- |
| 下载器测试失败 | WebUI 是否启用、地址能否从 ANI-RSS 访问、是否填写了 qBittorrent 的 `qbt_` API 密钥 |
| RSS 无法解析或请求超时 | 来源地址是否有效、运行 ANI-RSS 的设备能否访问源站；需要代理时配置[代理设置](/config/proxy) |
| 能预览条目，但没有下载任务 | 设置是否已保存、RSS 开关和订阅是否启用，以及匹配 / 排除规则、只下载最新集、已下载状态和延迟下载设置 |
| 下载器已收到任务，但无法下载 | qBittorrent 中的任务状态、错误信息、目录权限及种子可用性 |
| 集数或文件名不符合预期 | 订阅的季、集数偏移、[自定义集数规则](/custom-episode)和[重命名模板](/config/basic/rename) |
| 下载成功，但自动跳过或重命名异常 | 两个程序是否能通过相同路径访问媒体文件，目录是否可读写 |

更多问题见[常见问题](/faq)。

## 接下来可以做什么？

- **整理媒体库**：配置[重命名](/config/basic/rename)和[自动刮削](/config/basic/scrape)，方便 Emby、Jellyfin 等媒体服务识别。
- **接收更新提醒**：在[通知设置](/config/notification)中选择渠道与通知事件。
- **使用多个字幕组**：了解[备用 RSS 与自动洗版](/config/basic/rss#back-rss)，或[批量添加订阅](/batch-add)。
- **保存配置与订阅**：配置[备份与恢复](/config/basic/backup)，便于迁移或恢复数据。
